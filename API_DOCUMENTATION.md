# Claude Code Public API & Component Documentation

## Overview

This repository is a **research workspace** that contains:

1. Deep–dive technical analysis documents for the original, heavily-obfuscated *Claude Code v1.0.33* release.
2. The extracted / beautified source **chunks** (`stage1_analysis_workspace/chunks/*.mjs`).
3. A collection of **utility scripts** used throughout the analysis workflow (`stage1_analysis_workspace/scripts`).

Although the original upstream code is intentionally obfuscated, the helper scripts and documented artefacts form a set of *publicly consumable* APIs for anyone recreating or extending the analysis pipeline.  
This document enumerates those public entry-points, explains their purpose, lists the supported CLI parameters, and provides **copy-paste ready examples**.

> ℹ️  Names appearing inside the `chunks/` directory (e.g. `class Ao1`, `function wH2`) are *not* part of the stable public API – they merely reflect the upstream minified identifiers. Because they may change between dumps they are **excluded** from this formal reference.

## 1 · Utility CLI Scripts
All scripts live under `claude_code_v_1.0.33/stage1_analysis_workspace/scripts` and can be invoked via `node <script> [options]`.

| Script | Purpose | Key options |
|--------|---------|-------------|
| **`beautify.js`** | Pretty-prints a single large, minified `.mjs` file using *prettier* so that it becomes human-readable. | `input` (positional): path to input file  |
| **`split.js`** | Splits a beautified mega-file into smaller _annotated_ chunks (≈ 500 LOC each) for incremental analysis.  | `input` (positional): path to beautified file  |
| **`merge-again.js`** | Re-assembles previously split chunks back into one file – handy for fuzz-diff or quick test runs. | none (reads `chunks/index.json`) |
| **`ask.js`** | Thin wrapper around your favourite LLM – feeds a file / chunk to the model and stores the answer inside `analysis_results/`. | `--file <path>` – file(s) to analyse<br>`--prompt <string>` – custom prompt |
| **`learn-chunks.js`** | Calls `ask.js` iteratively for **all** chunks using a standard prompt, building cumulative knowledge. | `--model <id>` – override default LLM id |
| **`improve-merged-chunks.js`** | Post-processes the merged output, running lint / dead-code removal passes. | none |
| **`llm.js`** | Shared helper that abstracts the LLM invocation API (OpenAI, Anthropic, etc.). | exported function **`invoke(model, prompt)`** |

### 1.1 Usage Examples

Beautify original CLI mega-file:
```bash
node claude_code_v_1.0.33/stage1_analysis_workspace/scripts/beautify.js \
     claude_code_v_1.0.33/stage1_analysis_workspace/source/cli.mjs
```

Split the new beautified file into ~102 manageable chunks:
```bash
node claude_code_v_1.0.33/stage1_analysis_workspace/scripts/split.js \
     claude_code_v_1.0.33/stage1_analysis_workspace/cli.beautify.mjs
```

Run LLM analysis on *all* chunks in parallel (requires API key configured in env):
```bash
node claude_code_v_1.0.33/stage1_analysis_workspace/scripts/learn-chunks.js \
     --model gpt-4o-mini
```

## 2 · Programmatic Helper Functions (`llm.js`)

```javascript
// 1:25:claude_code_v_1.0.33/stage1_analysis_workspace/scripts/llm.js
// ... existing code ...
```

`llm.js` exposes a single **async** function:
```
invoke(modelId: string, prompt: string): Promise<string>
```

* Resolves with the raw textual response returned by the provider.
* Throws if the HTTP status ≠ 2xx or if a parsing error occurs.

Example:
```javascript
import { invoke } from "./scripts/llm.js";

const answer = await invoke("gpt-4o-mini", "Explain the TK2 class");
console.log(answer);
```

## 3 · Data Artefacts & Conventions

### 3.1 `chunks/*.mjs`
*Non-API* files produced by the splitter. They carry a header comment explaining their origin and index.

### 3.2 `analysis_results/`
Output folder generated by automated LLM passes. Contents are *ephemeral*; you may safely delete and regenerate them.

## 5 · FAQ / Troubleshooting

**Q 1: Why are class / function names unreadable?**  
The upstream source was minified. Use `beautify.js` + `split.js` first, then rely on the annotated analysis docs for semantic mapping.

**Q 2: How do I add a new analysis script?**  
Place it in the same `scripts/` folder, ensure it is `node` runnable, and document its CLI options in this file.
